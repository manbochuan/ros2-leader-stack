 一、② 项目规划
========================================================

【Leader 传给 ② 的输入】

   放在 input.prompt 里（App Completion API 唯一可靠的通道），
   同时在 input.biz_params 里放一份备份。

   prompt 里的内容 = ① 输出的 data 字段那一坨 JSON，形如：

   {"schema_version":"1.0",
    "project":{"name_en":"obstacle_avoidance","name_cn":"避障小车",
               "package_name":"obstacle_avoidance","difficulty":"入门",
               "description":"激光雷达检测障碍物距离并自动避障的两轮差速小车"},
    "modules":[
      {"module_name":"obstacle_detector",
       "function":"订阅激光雷达 /scan，计算最近障碍物距离并发布",
       "inputs":[{"topic":"/scan","message_type":"sensor_msgs/msg/LaserScan","description":"..."}],
       "outputs":[{"topic":"/obstacle_distance","message_type":"std_msgs/msg/Float32","description":"..."}],
       "dependencies":["rclpy","sensor_msgs","std_msgs"]},
      {"module_name":"motion_controller", "function":"...", "inputs":[...], "outputs":[...], "dependencies":[...]}
    ]}

   ★ 提示词/代码里请【从用户输入 / sys.query / prompt】读这段 JSON，
     宽容处理（字段缺失也不报错）。
   ★ 不要依赖"开始节点的自定义变量"（百炼 API 传不进去，我们试过 4 种形态）。


【② 必须输出的格式 —— 三段，顺序不能变】

   第 1 段：学习指南（纯 Markdown 文本，给学生看的）
   第 2 段：NODE_LIST 标记段
   第 3 段：PLAN_JSON 标记段

   具体长这样：

   ## 📚 项目学习指南

   ### 项目介绍
   ……

   <!--NODE_LIST_START-->
   {"nodes":[ …… 见下 …… ]}
   <!--NODE_LIST_END-->

   <!--PLAN_JSON_START-->
   {"plan":{ …… 见下 …… }}
   <!--PLAN_JSON_END-->

   ★ 字段名必须是：node_name / function / publish_topics / subscribe_topics / core_logic
     （不是 name / publishes / subscribes —— Leader 读的是前者）

   ★ Leader 会把这个 node 对象【原样】传给 ③（所以 ③ 收到的也是这些字段名）

   ★ nodes 不能是空数组（否则 Leader 报"没有 NODE_LIST 标记"）

========================================================
 二、③ 代码生成
========================================================

【Leader 传给 ③ 的输入】

   一次只给【一个节点】的规格。内容 = NODE_LIST 里的一个 node 对象，原样传：

   {"node_name":"obstacle_detector_node",
    "function":"订阅 /scan，计算最近障碍物距离并发布",
    "publish_topics":[{"topic":"/obstacle_distance","message_type":"std_msgs/msg/Float32"}],
    "subscribe_topics":[{"topic":"/scan","message_type":"sensor_msgs/msg/LaserScan"}],
    "core_logic":"定时器每 100ms 读一次 LaserScan"}

   ★ 同样从 prompt / 用户输入 里读


【③ 必须输出的格式】

   <!--ENV_START-->
   {
     "valid": true,
     "node_name": "obstacle_detector_node",
     "file_name": "obstacle_detector_node.py",
     "code": "import rclpy\nfrom rclpy.node import Node\n\n...",
     "summary": "一句话说明这个节点干什么",
     "teaching": "教学说明：涉及的知识点、新手易错点、运行方式"
   }
   <!--ENV_END-->

   失败时：

   <!--ENV_START-->
   {"valid": false, "node_name": "obstacle_detector_node", "error": "具体原因"}
   <!--ENV_END-->


【字段说明】

   valid     : bool   —— 是否成功（必填）
   code      : string —— 完整、可直接运行的 Python 代码（必填，含 import / 类 / main）
   file_name : string —— 文件名（建议填；不填 Leader 会用 node_name.py）
   summary   : string —— 一句话功能说明（建议填）
   teaching  : string —— 教学说明：知识点 + 易错点 + 运行方式（建议填）
   node_name : string —— 节点名（建议填；不填 Leader 会用请求里的名字补上）
   error     : string —— 失败原因（valid=false 时填）

   ★ code 里的换行要用 \n 转义（因为整个信封是 JSON）
   ★ 只有 ENV 标记段里的内容会被读，标记段外的文字随便写

 三、常见错误对照表
========================================================

 现象                                      原因
 ──────────────────────────────────────────────────────────────────
 Leader 报"② 输出里没有 NODE_LIST 标记"     标记段名字写错 / 没输出
                                            / JSON 不合法 / nodes 为空数组

 Leader 报"② 标记段解析失败"                标记段里的 JSON 不合法
                                            （注释 / 中文标点 / 尾逗号）

 Leader 报"③ 输出里没有 ENV 标记"           ENV 标记写错 / 没输出

 Leader 报"③ 信封不是合法 JSON"             ENV 里的 JSON 不合法

 ② 输出的是"模板文字"（全是 xxx）            输入没读到（见第四节）

 规划书里节点名显示"—"                       用了 name 而不是 node_name

 规划书里话题表格是空的                      用了 topics 而不是 topic_overview


========================================================
 四、输入读不到怎么办（重要）
========================================================

   Leader 调百炼工作流用的是 App Completion API，
   官方只保证 input.prompt 能可靠送达。

   所以工作流里读输入时，请优先从【用户输入 / prompt / sys.query】读，例如：
     · 百炼工作流开始节点的「用户输入」变量
     · 或者用「代码节点」从 sys.query 里取

   ★ 不要依赖"开始节点的自定义变量"（实测传不进去）
     （Leader 也会同时在 input.biz_params 里放一份备份，但那条路未验证可靠）

   ★ 建议写成"宽容读取"：
       先试自定义变量 → 有值就用
       → 没值就从 prompt / query 里解析 JSON
