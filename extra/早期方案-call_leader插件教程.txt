========================================================
 百炼自定义插件 call_leader 配置教程
 （让主 agent 能调用我们自己的编排服务）
========================================================

【这个插件干什么】

  主 agent 遇到"学生要做一个完整的 ROS2 项目"时，
  调这个插件 → 打到你服务器上的 Leader（:9200）→ 拿到规划书 → 展示给学生。

  链路：
    主 agent（百炼）
       ↓ call_leader 插件
      http://YOUR_HOST:9200/v1/chat/completions
       ↓
     Leader（你的服务器，编排大脑）
       ↓ 返回规划书
     主 agent 展示给学生


========================================================
 第 0 步：先确认 Leader 是通的（在服务器上跑）
========================================================

  curl -s --max-time 60 -X POST http://127.0.0.1:9200/v1/chat/completions \
    -H 'Content-Type: application/json' \
    -d '{"model":"leader","messages":[{"role":"user","content":"什么是 ROS2 的话题？"}]}' \
    | head -c 300

  → 应该返回一段 JSON，里面有 "choices":[{"message":{"content":"..."}}]

  ★ 如果这条不通，先别配插件（配了也没用）。

  ★ 顺便确认公网能访问（在服务器上跑）：
     curl -s -o /dev/null -w "HTTP %{http_code}\n" --max-time 30 \
       -X POST http://YOUR_HOST:9200/v1/chat/completions \
       -H 'Content-Type: application/json' \
       -d '{"model":"leader","messages":[{"role":"user","content":"hi"}]}'
     → 应该 HTTP 200
  ★ 如果这条不通：ufw allow 9200/tcp  （阿里云安全组也要放行 9200）


========================================================
 第 1 步：去百炼控制台
========================================================

  1. 打开 https://bailian.console.aliyun.com/
  2. 左侧「应用管理」→ 找到你的主 agent（appId 开头是 d97f8589…）
  3. 进去后，找「插件」/「工具」/「技能」这类入口
     （通常在应用编辑页的右侧栏，或者顶部标签页）

  ★ 不同版本界面位置可能不同，关键词是「插件」「工具」「自定义插件」


========================================================
 第 2 步：新建一个自定义插件
========================================================

  点「创建插件」/「新建自定义插件」，然后填：

  ┌─────────────────────────────────────────────────────┐
  │ 插件名称：      call_leader                          │
  │ 插件描述：      调用本项目的 ROS2 编排服务，处理需要   │
  │                 多步骤完成的完整项目需求（出规划书）。  │
  │                 只在"学生要做一个完整 ROS2 项目"时调用。│
  │ 鉴权方式：      无 / None（我们的 Leader 不需要 Key）  │
  └─────────────────────────────────────────────────────┘

  ★ 插件描述很重要 —— 大模型靠它判断"什么时候该调这个工具"。
    所以要写清楚"只在完整项目需求时调用"。


========================================================
 第 3 步：配置接口（两种界面，看你的像哪个）
========================================================

--------------------------------------------------------
 形态 A：填「URL + 请求体模板」的界面
--------------------------------------------------------

  ┌─────────────────────────────────────────────────────┐
  │ 请求方法：      POST                                 │
  │ 接口地址：      http://YOUR_HOST:9200/v1/chat/completions │
  │ Content-Type：  application/json                     │
  └─────────────────────────────────────────────────────┘

  请求体（Body）填：

  {
    "model": "leader",
    "messages": [
      {"role": "user", "content": "{{content}}"}
    ]
  }

  ★ {{content}} 是"插件参数"，见第 4 步。

  返回值取值路径（用来提取要展示给学生的文本）：

  choices[0].message.content

  ★ 如果界面上要写 JSONPath，就是：
     $.choices[0].message.content


--------------------------------------------------------
 形态 B：要 OpenAPI Schema 的界面
--------------------------------------------------------

  把下面这段贴进去（YAML）：

openapi: 3.0.0
info:
  title: call_leader
  description: 调用本项目的 ROS2 编排服务，处理需要多步骤完成的完整项目需求
  version: 1.0.0
servers:
  - url: http://YOUR_HOST:9200
paths:
  /v1/chat/completions:
    post:
      operationId: callLeader
      summary: 调用 ROS2 编排服务，为完整项目需求生成规划书
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                model:
                  type: string
                  description: 固定填 leader
                messages:
                  type: array
                  description: 对话消息
                  items:
                    type: object
                    properties:
                      role:
                        type: string
                        description: 固定填 user
                      content:
                        type: string
                        description: 学生的需求原文（可以是完整的一段话）
                    required:
                      - role
                      - content
              required:
                - messages
      responses:
        '200':
          description: 编排结果
          content:
            application/json:
              schema:
                type: object
                properties:
                  choices:
                    type: array
                    items:
                      type: object
                      properties:
                        message:
                          type: object
                          properties:
                            content:
                              type: string
                              description: 要展示给学生的完整内容


========================================================
 第 4 步：定义输入参数（关键）
========================================================

  插件需要一个参数，让主 agent 把"学生的需求"传进来。

  ┌─────────────────────────────────────────────────────┐
  │ 参数名：        content                              │
  │ 类型：          string                               │
  │ 是否必填：      是                                    │
  │ 描述：          学生的需求原文。例如"帮我做一个避障小车。│
  │                 学生水平：入门级"。只在完整项目需求时填。│
  └─────────────────────────────────────────────────────┘

  ★ 参数名要和第 3 步请求体里的 {{content}} 对上（大小写敏感）。
  ★ 描述里写清"何时填什么"，大模型才知道怎么传。


========================================================
 第 5 步：测试插件
========================================================

  界面上通常有个「测试」/「调试」按钮。填：

  参数 content = 帮我做一个避障小车

  点测试 → 应该返回一段规划书文本（含节点清单、话题总览等）。

  ★ 如果返回的是 JSON 原文没被解析出来
     → 检查"返回值取值路径"是不是 choices[0].message.content

  ★ 如果报超时
     → Leader 出规划书要 20~90 秒，把插件的超时调到 120 秒以上

  ★ 如果报 401/403
     → 检查鉴权方式是不是配成了"需要 Key"（我们的 Leader 不要）

  ★ 如果报连接失败
     → 检查 9200 是否放行（ufw + 阿里云安全组）


========================================================
 第 6 步：把插件加到主 agent 上
========================================================

  回到主 agent 的编辑页 → 在「插件」/「工具」列表里
  勾选/添加刚创建的 call_leader。

  确认它和 ask_platform 一起出现在工具列表里。


========================================================
 第 7 步：更新主 agent 的提示词
========================================================

  把【主agent提示词-v6-含call_leader.txt】的内容
  整个复制粘贴到主 agent 的「人设与回复逻辑」/「提示词」框里。

  ★ 这份提示词已经写好了：
     · 什么时候调 call_leader（完整项目）
     · 什么时候调 ask_platform（单节点代码 / 其他领域）
     · 什么时候自己答（ROS2 概念、报错、闲聊）
     · 拿到规划书后怎么追（后面的节点生成走 ask_platform）
     · 失败怎么处理


========================================================
 第 8 步：发布应用（★ 千万别忘）
========================================================

  右上角「发布」→ 确认。

  ★ 改了插件或提示词，必须重新发布，API 调用才会用新版本。
  ★ 不发布的话，平台调到的还是旧版（这个坑我们踩过）。


========================================================
 第 9 步：验证
========================================================

  ★ 方式 1：直接在百炼对话框里测

     问："帮我做一个避障小车"
     → 应该看到它调用了 call_leader，然后输出规划书

  ★ 方式 2：从叮当端到端测

     先去叮当网页给我们的智能体提问：
     "帮我做一个避障小车"
     → 平台 → 【主 agent 的入口】:8445 → shim → 百炼主 agent
     → 主 agent 调 call_leader → Leader
     → 返回规划书

  ★ 方式 3：看 Leader 的日志（确认它被调用了）
     在服务器上：
       journalctl -u leader -n 20 --no-pager
     → 应该看到 "OpenAI 兼容入口：session=... text=帮我做一个避障小车"


========================================================
 常见问题
========================================================

Q1：插件测试通了，但叮当那边调不到 Leader？
    → 大概率是应用没发布。重新发布一次。

Q2：主 agent 不调 call_leader，还是用 ask_platform？
    → 提示词里的"什么时候调"写得不够明确，
      或者插件的"描述"没写清。
      可以把插件描述改成：
      "只在学生要做一个完整的 ROS2 项目（多节点协作、需要规划书）时调用。
       单个节点的代码不要用这个工具。"

Q3：调 call_leader 后，学生回复"A"（确认规划），
    主 agent 又调 call_leader，结果 Leader 忘了规划？
    → 这是【已知设计】。Leader 的每次调用都是独立的一次。
      正确做法：确认规划后生成节点，走 ask_platform（提示词里已写明）。
      主 agent 自己记住节点清单。

Q4：Leader 出规划书要多久？
    → 20~90 秒（如果它还要转平台找搭档，可能更久）。
      插件的超时建议设 120 秒以上。

Q5：能不能让 Leader 支持多轮（记住上一次）？
    → 可以，但要改插件的请求体，加一个 "user" 字段当会话 ID。
      需要百炼插件支持引用"对话 ID"变量。
      目前先按单轮设计（出规划书 → 后续走 ask_platform）。


========================================================
 一句话总结
========================================================

  1. 新建自定义插件 call_leader
  2. URL = http://YOUR_HOST:9200/v1/chat/completions
  3. 请求体 = {"model":"leader","messages":[{"role":"user","content":"{{content}}"}]}
  4. 取值 = choices[0].message.content
  5. 参数 = content（学生的需求原文）
  6. 加到应用上 + 换提示词 + 【发布】
  7. 测："帮我做一个避障小车"
